# lr-crop-calculator

MediaPipeで人物を自動検出し、Lightroom Classicで非破壊クロップを一括適用するためのツールセットです。

Pythonスクリプトで画像を解析してクロップ情報のCSVを作り、Lightroomプラグインでそれを
カタログに適用します。元のJPGファイルには一切変更を加えません。

- 元のJPG本体は無加工(読み取りのみ)。クロップはLightroomのカタログ内メタデータとして適用
- 出力アスペクト比は常に元画像と同一(ズームイン/ズームアウトのみでクロップ)
- EXIF Orientation(スマートフォン等の回転情報付き画像)に対応
- 用途に応じて2つのクロップモードを選択可能

## クロップモード

| | general(既定) | promo |
|---|---|---|
| 構図の決め方 | 手動クロップ実績を学習したモデルで予測 | 固定ルール(定数で調整) |
| 水平配置 | 手動クロップ実績どおりの左右配置を再現 | 人物全体の中心を画像の中央に合わせる |
| 余白 | 学習結果+背景の情報量(エッジ密度)で調整 | 上下左右とも約10%(`MARGIN_RATIO`) |
| 用途 | 撮影ごとの構図に合わせたい場合 | 宣材写真など、規格を揃えたい場合 |

出力CSVの形式は両モードで同一なので、Lightroom側の適用手順は変わりません。

- generalモードの詳細 → [汎用ポートレートクロップ(general)](#汎用ポートレートクロップgeneral)
- promoモードの詳細 → [宣材写真用クロップ(promo)](#宣材写真用クロップpromo)

## リポジトリ構成

```
lr-crop-calculator/
├── crop_calculator.py          ... 画像を解析してクロップ情報CSVを生成するメインスクリプト
├── general_crop.py             ... generalモードの特徴量抽出・クロップ計算ロジック
├── train_general_crop_model.py ... 手動トリミング実績からgeneralモード用モデルを学習する
├── promo_refine.py             ... promoモードの結果を手動クロップ実績で微調整するロジック
├── train_promo_refine.py       ... promo微調整モデルを学習する
├── evaluate_crop.py            ... 手動クロップ実績に対する精度を測定・交差検証する
├── debug_single.py             ... 1枚の画像を詳細診断するデバッグ用スクリプト
├── requirements.txt            ... 依存パッケージ
├── LICENSE                     ... MITライセンス
├── .gitignore
├── Info.lua                    ... Lightroomプラグイン定義
├── ApplyCropFromCSV.lua        ... CSVを読み込みクロップを適用する本体
└── ExportCropHistory.lua       ... カタログのクロップ履歴をCSVに書き出す(学習データ作成用)
```

末尾のLua 3ファイルが、あわせて1つのLightroomプラグインを構成します。

# 使い方

## 1. セットアップ

```bash
pip install -r requirements.txt
```

初回実行時、姿勢推定モデル(`pose_landmarker_full.task`、約9MB)をGoogleのサーバーから
自動ダウンロードします。インターネット接続が必要です。

`scikit-learn` はgeneralモードの学習済みモデルを使う/学習する場合のみ必要です
(モデルが無い場合、generalモードはヒューリスティックで動作します)。

## 2. クロップ情報CSVの生成

```bash
python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv
```

| オプション | 内容 |
|---|---|
| `--input` | JPG画像が入ったフォルダ(必須) |
| `--output` | 出力CSVのパス(既定: `crop_data.csv`) |
| `--recursive` | サブフォルダも再帰的に処理する |
| `--mode` | `general`(既定)または `promo` |
| `--model` | generalモード用の学習済みモデル。省略時はスクリプトと同じフォルダの `general_crop_model.pkl` を探す |
| `--refine-model` | promoモードの微調整モデル。省略時は `promo_refine_model.pkl` を探す([詳細](#手動クロップ実績による微調整promo)) |
| `--no-detect-fallback` | 人物検出の再試行を無効にする([詳細](#人物検出のフォールバック)) |

```bash
# 宣材写真用の固定ルールで生成する場合
python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv --mode promo
```

### 出力CSVの列

| 列名 | 内容 |
|---|---|
| filename | ファイル名(拡張子含む) |
| path | 元画像の絶対パス。Lightroom側はこの**フルパス**で写真を特定します |
| CropTop / CropLeft / CropRight / CropBottom | 画像全体を0.0〜1.0とした場合のクロップ枠の各辺の位置 |
| full_body | 1=全身写真と判定, 0=それ以外 |
| status | OK / NO_PERSON_DETECTED(人物検出失敗。この行はLightroom側でスキップされます) |
| detect_stage | 検出に使った段階。0=通常条件。1以上は再試行で検出したもの([詳細](#人物検出のフォールバック)) |

`status` が `NO_PERSON_DETECTED` の行はクロップが計算されていません。該当写真は
手動でトリミングするか、そのまま未クロップにしておいてください。

## 3. Lightroomプラグインのインストール

1. このリポジトリのフォルダをそのまま任意の場所にコピーし、フォルダ名の末尾を
   `.lrplugin` にリネームします(例: `CropFromCSV.lrplugin`)。
   Pythonスクリプトと同じフォルダに置いたままで構いません。
2. Lightroom Classic の `ファイル > プラグインマネージャー` から「追加」を選び、上記フォルダを指定します。
3. 対象のJPGを、通常どおりLightroomのカタログに読み込んでおきます(まだの場合)。

インストールすると `ファイル > 追加ツール` に2つのメニュー項目が追加されます。

- **CSVからクロップを適用...**(`ApplyCropFromCSV.lua`)
- **クロップ履歴をCSVに書き出す...**(`ExportCropHistory.lua`) — 学習データの作成用

> プラグインのコードを更新したときは、プラグインマネージャーで「再読み込み」してください。
> Lightroomはコードをメモリに保持しているため、ファイルを書き換えただけでは反映されません。

## 4. クロップの適用

1. `ファイル > 追加ツール > CSVからクロップを適用...` を選択します。
2. 手順2で生成した `crop_data.csv` を選択します。
3. マッチ件数の確認ダイアログで内容を確認し、「適用する」を押します。
4. 完了後、適用件数・エラー件数のサマリーが表示されます。

### 適用時の注意点

- **必ず事前にカタログのバックアップを取り**、まず数枚〜数十枚で動作確認してから
  全件に適用することを強く推奨します。
- 写真の特定には**フルパス**(CSVの`path`列)を使用します。Canonなどの連番ファイル名は
  撮影日フォルダをまたいで重複することが多く(例: `052A7463.JPG` が複数フォルダに存在)、
  ファイル名だけで照合すると**別フォルダの同名写真にクロップが適用されてしまう**ためです。
  - 適用前の確認ダイアログに「フルパスで特定: N件 / ファイル名で特定: N件」が表示されるので、
    意図した方法で照合されているか確認できます。
  - `path`列が無い旧形式のCSVではファイル名照合にフォールバックしますが、カタログ内に
    同名ファイルが複数ある写真は誤適用を避けるためスキップされます。その場合は
    `crop_calculator.py` を再実行してCSVを作り直してください。
- 元のJPG本体は変更されません。ただしLightroomの「カタログ設定 > メタデータ >
  変更を自動的にXMPに書き込む」がオンの場合、JPGファイル内のXMPメタデータに編集情報が
  書き込まれます(ピクセルデータは変更されません)。元ファイルに一切触れたくない場合は
  この設定をオフにしてください。
- Lightroom Classic のバージョンにより `photo:applyDevelopSettings` の挙動が異なる場合が
  あります。手元の環境で少数サンプルでのテストをお願いします。

# クロップロジック

## 汎用ポートレートクロップ(general)

`--mode` を省略したときに使われる既定のモードです。手動クロップ実績から学習したモデルで、
人物のバウンディングボックスに対する上下左右の余白を予測します。

### 手動トリミング実績を学習データにする

既にLightroomで手動トリミング済みの写真があれば、その実績をそのまま学習データにできます。

**手順1: クロップ履歴を書き出す**

`ファイル > 追加ツール > クロップ履歴をCSVに書き出す...`(`ExportCropHistory.lua`)を実行します。
対象は選択中の写真(未選択ならフォルダ/コレクション内の全写真)なので、事前に手動トリミング済みの
写真が入ったフォルダ/コレクションを選んでおくと絞り込めます。

出力されるCSVには、ファイル名・元ファイルパス・実際のクロップ値・クロップ済みかどうかの
フラグが入ります。カタログやJPGへの書き込みは一切行いません(読み取り専用)。

**手順2: モデルを学習する**

```bash
pip install scikit-learn
python train_general_crop_model.py --crop-csv crop_history.csv \
    --images-dir /path/to/jpg_folder --output-model general_crop_model.pkl
```

各写真について人物検出を行い、実際のクロップ矩形を「人物のバウンディングボックスに対する
上下左右の余白比率」に変換したうえで、4つの軽量な回帰モデル(勾配ブースティング木)を
学習します。回転クロップ(`CropAngle` が0でない)やクロップされていない写真は自動的に
除外されます。

実行後、ホールドアウトデータでのMAE(誤差)と、実際のクロップ枠とのIoU(重なり度、
1.0に近いほど良い)が表示されるので、精度の目安として確認してください。

`--images-dir` は、CSVの `path` 列が(別のPCで書き出した等の理由で)使えない場合の
フォールバック検索先です。通常は `path` 列だけで解決できます。

**手順3: 学習したモデルを使う**

モデルをスクリプトと同じフォルダに置けば、`--model` の指定なしで自動的に使われます。

```bash
python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv
```

写真を追加でトリミングしたら、手順1〜2を再実行すればモデルを更新できます。

### モデルなしで使う(ヒューリスティック)

学習済みモデルが無い場合も、そのまま動作します。人物のポーズ検出に加えて、Pillowベースの
簡易エッジ密度解析で「背景のうるささ」を推定し、経験則(三分割法+視線方向+背景密度)で
クロップを決めます。

学習済みモデルは生成物のためリポジトリに含まれていません。**クローンした直後はこの
ヒューリスティックで動作します**。実行時にどちらを使っているかがコンソールに表示されます。

### 水平方向の配置

既定では、**手動クロップ実績どおりの左右配置**を再現します(予測された左右の余白が、
クロップの幅と位置の両方を決めます)。

人物を厳密に画像の水平中央へ置きたい場合は、`general_crop.py` の
`HORIZONTAL_CENTER_WEIGHT` を `1.0` にしてください(`0.0`〜`1.0` の中間値で両者を混合)。
この場合もクロップの**幅は変わりません**(位置だけが変わり、画像外にはみ出すときは
画像内に収めます)。promoモードは常に人物全体の中心を画像中央に配置します。

厳密な中央配置を既定にしていないのは、手動クロップを分析した結果、クロップ中心からの
ズレが鼻4.2% / 肩の中点5.7% / 体bbox中心4.5%(いずれも平均)であり、特定の基準を
厳密に中央へ置く構図ではなく「ゆるやかに中央寄り」だったためです。

### 制限・チューニングのヒント

- 背景の「情報量」は、本格的な顕著性(サリエンシー)モデルではなく、Pillowのエッジ検出に
  よる簡易近似です(追加の重い依存を避けるため)。特定の被写体(強いボケ、逆光、単色背景など)
  でうまく機能しない場合は `general_crop.py` 冒頭の `BAND_RATIO` /
  `DENSITY_ADJUST_STRENGTH` 等の定数を調整してください。
- 1000枚規模のデータがあれば実用的な精度が見込めますが、データが少ない/偏っている場合は
  特定の構図(全身、逆光など)に対する予測が不安定になることがあります。`full_body`
  (全身/半身)ごとに枚数のバランスが取れていると学習が安定しやすいです。
- 複数人物が写っている写真は、ポーズ検出が最も信頼度の高い1人のみを対象にするため、
  意図と異なる人物を基準にクロップされる可能性があります。
- 予測結果は学習データの傾向に強く依存します。学習データに含まれない極端な構図では
  精度が落ちる点にご留意ください。

## 宣材写真用クロップ(promo)

固定ルールでクロップを決める従来ロジックです。学習データを必要としません。

- 水平方向: **人物全体(バウンディングボックス)の中心**を画像の水平中央に配置します。
  人物が斜め・横向きでも左右に偏りません
  - 人物が画像の端に寄っていると、中央に置いたクロップ枠が画像からはみ出します。
    その場合は枠を詰めて中央に寄せますが、アスペクト比固定のため幅を詰めると高さも
    同率で縮み、余白が狭くなります。そのため `CENTER_SHRINK_MIN_MARGIN`(既定2%)の
    余白を確保できる範囲でのみ枠を詰めます
  - どう詰めても中央配置できない写真(人物が端に寄りすぎている場合)は、
    **人物が切れないことを優先**して中央から多少ずらします。人物が切れることはありません
  - `CENTER_SHRINK_MIN_MARGIN` を `0.0` にすると中央配置を最優先します(人物に接する
    ぎりぎりまで枠を詰める)。ただしバウンディングボックスはランドマーク基準のため、
    髪や衣服が実際にはその外側にはみ出す点にご注意ください
- 全身写真: 人物が絶対に切れないことを優先しつつ、上下・左右ともに約10%の余白を確保
  (人物のプロポーションと画像アスペクト比の関係で、片方の余白が10%より大きくなることがあります)
- 全身でない写真: 頭上の余分な余白を削除しつつ上部余白を約10%確保。下端はヒップの
  ランドマークが検出できればそこを目安にし(脚やスカートが写っていてもそこまでは含めない、
  半身ポートレート風の仕上がり)、ヒップが見えていない場合はそのまま見えている範囲を使います

パラメータは `crop_calculator.py` 冒頭の定数で調整できます(余白率は `MARGIN_RATIO = 0.10`)。
検出精度に納得できない場合は `VISIBILITY_THRESHOLD` や `HEAD_PAD_FACTOR` を数枚のサンプルで
試しながら調整することをおすすめします。

複数人が写っている場合は、検出した全員(最大 `MAX_PERSONS` 人)のバウンディングボックスを
統合してから上記のロジックを適用します。背景に小さく写り込んだ人物で構図が破綻しないよう、
最も大きい人物に対して高さが `MIN_PERSON_HEIGHT_RATIO` 未満の人物は除外します。

### 手動クロップ実績による微調整(promo)

固定ルールだけでは、半身写真や複数人写真で「写真ごとの判断」が残ります。手動クロップ実績が
あれば、その差分を学習して自動的に補正できます。

```bash
pip install scikit-learn
python train_promo_refine.py --crop-csv hand_crop.csv --cross-validate
```

`promo_refine_model.pkl` がスクリプトと同じフォルダにあれば、`--mode promo` 実行時に
自動的に使われます(無い場合は従来どおり固定ルールのみで動作します)。

実測での改善幅(手動クロップ789枚、5分割交差検証):

| 区分 | 枚数 | 微調整なし | 微調整あり |
|---|---|---|---|
| 全体 | 789 | 0.9098 | **0.9367** |
| 全身 | 366 | 0.9572 | 0.9626 |
| 半身 | 423 | 0.8689 | **0.9142** |
| 複数人 | 22 | 0.7405 | **0.8623** |

仕組みの要点:

- クロップ枠をゼロから予測するのではなく、**promoの結果からのズレ(差分)だけ**を学習します。
  予測すべき量が小さく精度を出しやすいうえ、モデルが外しても promo の結果から大きく離れません
- 予測するのは「中心の水平ズレ / 中心の垂直ズレ / 拡大率」の**3つだけ**です。4辺を独立に
  予測するとアスペクト比固定の制約が壊れるため、枠を一意に決められる最小の組にしています
- 予測後も人物が切れないよう調整されるため、**微調整によって人物が切れることはありません**

### 精度の測定と検証

`evaluate_crop.py` で、手動クロップ実績に対する精度を測定できます。

```bash
# 現状の精度(全身/半身/複数人の区分別、中央値・下位10%・最小も表示)
python evaluate_crop.py --crop-csv hand_crop.csv --worst 10

# 定数の最適値を探し、過学習でないか交差検証する
python evaluate_crop.py --crop-csv hand_crop.csv --cross-validate     --sweep MARGIN_RATIO=0.09,0.10,0.11
```

連番ブロック単位で分割して交差検証します。連続する写真は同じ衣装・セットアップでほぼ同一
構図になるため、ランダム分割では学習側と評価側に実質同じ写真が入り、検証になりません。

人物検出の結果はキャッシュされるので、2回目以降のパラメータ掃引は一瞬で終わります。

# 補足

## 人物検出のフォールバック

ハイキー(白飛び気味)で低コントラストな写真では、人物がはっきり写っていても通常の条件では
検出に失敗することがあります。そのため検出に失敗した場合のみ、「画像の縮小」
「コントラスト強調」「閾値の緩和」を順に試します。

- 1段階目は通常の条件そのものなので、**通常条件で検出できる写真の結果は一切変わりません**
- 再試行で検出した写真は `detect_stage` 列が 1 以上になります。通常より検出精度が落ちている
  可能性があるため、**クロップ結果の確認をおすすめします**(実行後のサマリーにも該当ファイル名が
  一覧表示されます)
- 閾値を緩めると、顔の一部や背景の模様を人物と誤認することがあります。これを防ぐため、
  再試行で得た結果には妥当性チェック(肩と頭部が見えている・一定数以上のランドマークがある・
  人物が極端に小さくない)を課し、満たさない場合は採用せず `NO_PERSON_DETECTED` とします。
  誤検出で壊滅的なクロップになるより、未クロップで残す方が安全なためです
- `--no-detect-fallback` を付けると、この再試行を無効にできます

## EXIF Orientationへの対応

スマートフォンや一部のカメラで撮影した写真は、ピクセルデータ自体は横向きのまま保存され、
EXIFのOrientationタグで「表示時にどう回転するか」を指定していることがあります。

Lightroomの `crs:CropTop/Left/Right/Bottom` はこの**保存時(回転補正前)の座標系**を基準に
解釈されるため、本スクリプトは以下の手順で変換しています。

1. EXIF Orientationを読み取り、表示向き(見たまま)に回転補正した画像で人物検出・クロップ計算を行う
2. 計算結果を、Orientationタグに応じて保存時の座標系に変換してからCSVに出力する

通常は特に意識する必要はありません。疑わしい写真があれば、`debug_single.py` が表示向き座標・
raw座標の両方を出力するので確認してみてください。

## デバッグツール

`debug_single.py` を使うと、1枚の写真に対する検出結果(全ランドマークの座標・visibility・
presence)、計算されたバウンディングボックス、full_body判定、クロップ範囲(表示向き座標・
raw座標の両方)をコンソールに出力し、検出結果を重ねた確認用画像を保存できます。
クロップ位置がおかしいと感じたときの切り分けに使ってください。

```bash
python debug_single.py --input path/to/photo.jpg --output debug_out.jpg
```

`crop_calculator.py` と同じく `--mode general`(既定)/ `--mode promo` に対応しています。
generalモードでは、判定に使った特徴量(視線方向・背景密度など)と予測された余白、および
人物検出に再試行を使ったかどうかも表示します。
