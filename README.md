# lr-crop-calculator

MediaPipeで人物を自動検出し、Lightroom Classicで非破壊クロップを一括適用するためのツールセットです。

Pythonスクリプトで画像を解析してクロップ情報のCSVを作り、Lightroomプラグインでそれを
カタログに適用します。元のJPGファイルには一切変更を加えません。

- 元のJPG本体は無加工(読み取りのみ)。クロップはLightroomのカタログ内メタデータとして適用
- 出力アスペクト比は常に元画像と同一(ズームイン/ズームアウトのみでクロップ)
- 複数人が写っている写真は全員を収める
- EXIF Orientation(スマートフォン等の回転情報付き画像)に対応

## クロップモード

| | general(既定) | promo |
|---|---|---|
| 構図の決め方 | 手動クロップ実績を学習したモデルで予測 | 固定ルール(定数で調整) |
| 水平配置 | 手動クロップ実績どおりの左右配置を再現 | 人物全体の中心を画像の中央に合わせる |
| 余白 | 学習結果+背景の情報量(エッジ密度)で調整 | 上下左右とも約10%(`MARGIN_RATIO`) |
| 用途 | 撮影ごとの構図に合わせたい場合 | 宣材写真など、規格を揃えたい場合 |

出力CSVの形式は両モードで同一なので、Lightroom側の適用手順は変わりません。

## リポジトリ構成

```
lr-crop-calculator/
├── crop_calculator.py          ... 画像を解析してクロップ情報CSVを生成するメインスクリプト
├── general_crop.py             ... generalモードのクロップ計算
├── train_general_crop_model.py ... generalモード用モデルを学習する
├── promo_refine.py             ... promoモードの結果を手動クロップ実績で微調整する
├── train_promo_refine.py       ... promo微調整モデルを学習する
├── evaluate_crop.py            ... 手動クロップ実績に対する精度を測定・検証する
├── debug_single.py             ... 1枚の画像を詳細診断するデバッグ用スクリプト
├── requirements.txt
├── LICENSE
├── .gitignore
├── Info.lua                    ... Lightroomプラグイン定義
├── ApplyCropFromCSV.lua        ... CSVを読み込みクロップを適用する
└── ExportCropHistory.lua       ... カタログのクロップ履歴をCSVに書き出す
```

末尾のLua 3ファイルが、あわせて1つのLightroomプラグインを構成します。

# 使い方

## 1. セットアップ

```bash
pip install -r requirements.txt
```

初回実行時、姿勢推定モデル(`pose_landmarker_full.task`、約9MB)をGoogleのサーバーから
自動ダウンロードします。インターネット接続が必要です。

`scikit-learn` は学習済みモデルを使う/学習する場合のみ必要です。

## 2. クロップ情報CSVの生成

```bash
python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv
```

| オプション | 内容 |
|---|---|
| `--input` | JPG画像が入ったフォルダ(必須) |
| `--output` | 出力CSVのパス(既定: `crop_data.csv`) |
| `--recursive` | サブフォルダも再帰的に処理する |
| `--mode` | `general`(既定)または `promo` |
| `--model` | generalモード用モデル。省略時は `general_crop_model.pkl` を探す |
| `--refine-model` | promoモード用の微調整モデル。省略時は `promo_refine_model.pkl` を探す |
| `--no-detect-fallback` | 人物検出の再試行を無効にする |

### 出力CSVの列

| 列名 | 内容 |
|---|---|
| filename | ファイル名(拡張子含む) |
| path | 元画像の絶対パス。Lightroom側はこの**フルパス**で写真を特定します |
| CropTop / CropLeft / CropRight / CropBottom | 画像全体を0.0〜1.0とした場合のクロップ枠の各辺の位置 |
| full_body | 1=全身写真と判定, 0=それ以外 |
| status | OK / NO_PERSON_DETECTED(人物検出失敗。この行はLightroom側でスキップされます) |
| detect_stage | 検出に使った段階。0=通常条件。1以上は再試行で検出したもの |

`status` が `NO_PERSON_DETECTED` の行はクロップが計算されていません。該当写真は
手動でトリミングするか、そのまま未クロップにしておいてください。

## 3. Lightroomプラグインのインストール

1. このリポジトリのフォルダをそのまま任意の場所にコピーし、フォルダ名の末尾を
   `.lrplugin` にリネームします(例: `CropFromCSV.lrplugin`)。
2. Lightroom Classic の `ファイル > プラグインマネージャー` から「追加」を選び、上記フォルダを指定します。
3. 対象のJPGを、通常どおりLightroomのカタログに読み込んでおきます。

インストールすると `ファイル > 追加ツール` に2つのメニュー項目が追加されます。

- **CSVからクロップを適用...**(`ApplyCropFromCSV.lua`)
- **クロップ履歴をCSVに書き出す...**(`ExportCropHistory.lua`) — 学習データの作成用

> プラグインのコードを更新したときは、プラグインマネージャーで「再読み込み」してください。
> Lightroomはコードをメモリに保持しているため、ファイルを書き換えただけでは反映されません。

## 4. クロップの適用

1. `ファイル > 追加ツール > CSVからクロップを適用...` を選択します。
2. 生成した `crop_data.csv` を選択します。
3. マッチ件数の確認ダイアログで内容を確認し、「適用する」を押します。

### 注意点

- **必ず事前にカタログのバックアップを取り**、まず数枚〜数十枚で動作確認してから
  全件に適用してください。
- 写真の特定には**フルパス**(CSVの`path`列)を使用します。Canonなどの連番ファイル名は
  撮影日フォルダをまたいで重複することが多く、ファイル名だけで照合すると別フォルダの
  同名写真に適用されてしまうためです。適用前の確認ダイアログに「フルパスで特定: N件 /
  ファイル名で特定: N件」が表示されます。
- 元のJPG本体は変更されません。ただしLightroomの「カタログ設定 > メタデータ >
  変更を自動的にXMPに書き込む」がオンの場合、JPGファイル内のXMPメタデータに編集情報が
  書き込まれます(ピクセルデータは変更されません)。

# クロップロジック

## 汎用ポートレートクロップ(general)

`--mode` を省略したときに使われる既定のモードです。手動クロップ実績から学習したモデルで、
人物のバウンディングボックスに対する上下左右の余白を予測します。

学習済みモデルが無い場合も動作します。その場合は人物のポーズ検出に加えて、Pillowベースの
簡易エッジ密度解析で背景の情報量を推定し、経験則(三分割法+視線方向+背景密度)で
クロップを決めます。実行時にどちらを使っているかがコンソールに表示されます。

### 水平方向の配置

既定では、手動クロップ実績どおりの左右配置を再現します(予測された左右の余白が、
クロップの幅と位置の両方を決めます)。

人物を厳密に画像の水平中央へ置きたい場合は、`general_crop.py` の
`HORIZONTAL_CENTER_WEIGHT` を `1.0` にしてください(`0.0`〜`1.0` の中間値で両者を混合)。
この場合もクロップの幅は変わらず、位置だけが変わります。

### 制限

- 背景の「情報量」は、顕著性モデルではなくPillowのエッジ検出による簡易近似です。
  特定の被写体でうまく機能しない場合は `general_crop.py` 冒頭の `BAND_RATIO` /
  `DENSITY_ADJUST_STRENGTH` 等を調整してください。
- 予測結果は学習データの傾向に依存します。学習データに含まれない極端な構図では
  精度が落ちます。

## 宣材写真用クロップ(promo)

固定ルールでクロップを決めます。学習データがなくても動作します。

- **水平方向**: 人物全体(バウンディングボックス)の中心を画像の水平中央に配置します。
  人物が斜め・横向きでも左右に偏りません。
  - 人物が画像の端に寄っていると、中央に置いた枠が画像からはみ出します。その場合は
    `CENTER_SHRINK_MIN_MARGIN`(既定2%)の余白を確保できる範囲で枠を詰めて中央に寄せます。
  - どう詰めても中央配置できない場合は、**人物が切れないことを優先**して中央から
    多少ずらします。人物が切れることはありません。
- **全身写真**: 上下・左右ともに約10%の余白を確保します(人物のプロポーションと画像の
  アスペクト比の関係で、片方の余白が10%より大きくなることがあります)。
- **全身でない写真**: 頭上の余分な余白を削除しつつ上部余白を約10%確保。下端はヒップの
  ランドマークを目安にします(脚やスカートが写っていてもそこまでは含めない、半身
  ポートレート風の仕上がり)。

複数人が写っている場合は、検出した全員(最大 `MAX_PERSONS` 人)のバウンディングボックスを
統合してから上記を適用します。背景に小さく写り込んだ人物で構図が破綻しないよう、最も
大きい人物に対して高さが `MIN_PERSON_HEIGHT_RATIO` 未満の人物は除外します。

主な調整用の定数は `crop_calculator.py` の冒頭にあります(`MARGIN_RATIO`、
`FOOT_PAD_RATIO`、`VISIBILITY_THRESHOLD`、`HEAD_PAD_FACTOR` など)。

### 手動クロップ実績による微調整

固定ルールだけでは、半身写真や複数人写真で写真ごとの判断が残ります。手動クロップ実績が
あれば、その差分を学習して自動的に補正できます。半身・複数人で特に効果があります。

```bash
pip install scikit-learn
python train_promo_refine.py --crop-csv hand_crop*.csv --cross-validate
```

`promo_refine_model.pkl` がスクリプトと同じフォルダにあれば、`--mode promo` 実行時に
自動的に使われます(無い場合は固定ルールのみで動作します)。

仕組みの要点:

- クロップ枠をゼロから予測するのではなく、**promoの結果からのズレ(差分)だけ**を学習します。
  モデルが外しても promo の結果から大きく離れません。
- 予測するのは「中心の水平ズレ / 中心の垂直ズレ / 拡大率」の**3つだけ**です。4辺を独立に
  予測するとアスペクト比固定の制約が壊れるためです。
- 予測後も人物が切れないよう調整されます。

精度を上げるには、手動クロップの枚数を増やすのが最も効果的です。撮影のたびに手直しした
結果を書き出し、上記コマンドを再実行すればモデルを更新できます。

# 学習データの作り方

既にLightroomで手動トリミング済みの写真があれば、その実績をそのまま学習データにできます。

**1. クロップ履歴を書き出す**

`ファイル > 追加ツール > クロップ履歴をCSVに書き出す...`(`ExportCropHistory.lua`)を実行します。
対象は選択中の写真(未選択ならフォルダ/コレクション内の全写真)です。カタログやJPGへの
書き込みは一切行いません(読み取り専用)。

**2. モデルを学習する**

```bash
# promoモードの微調整モデル(複数の撮影日のCSVをまとめて指定できます)
python train_promo_refine.py --crop-csv hand_crop*.csv --cross-validate

# generalモードのモデル
python train_general_crop_model.py --crop-csv hand_crop.csv \
    --images-dir /path/to/jpg_folder --output-model general_crop_model.pkl
```

回転クロップ(`CropAngle` が0でない)とクロップされていない写真は自動的に除外されます。
学習済みモデルはリポジトリに含まれていないため、クローンした直後は固定ルール/
ヒューリスティックで動作します。

# 精度の測定と検証

`evaluate_crop.py` で、手動クロップ実績に対する精度をIoU(重なり度、1.0に近いほど良い)で
測定できます。

```bash
# 現状の精度(全身/半身/複数人の区分別、中央値・下位10%・最小も表示)
python evaluate_crop.py --crop-csv hand_crop*.csv --worst 10

# 定数の最適値を探し、過学習でないか交差検証する
python evaluate_crop.py --crop-csv hand_crop*.csv --cross-validate \
    --sweep MARGIN_RATIO=0.09,0.10,0.11
```

交差検証は、撮影日が2つ以上あれば**撮影日単位**で分割します(学習に使っていない別の
撮影日に通用するかを見る、実運用に近い検証)。撮影日が1つだけなら連番ブロック単位で
分割します。連続する写真は同じ衣装・セットアップでほぼ同一構図になるため、ランダム分割
では学習側と評価側に実質同じ写真が入り、検証になりません。

人物検出の結果はキャッシュされるので、2回目以降のパラメータ掃引は一瞬で終わります。

# 補足

## 人物検出のフォールバック

ハイキー(白飛び気味)で低コントラストな写真では、人物がはっきり写っていても通常の条件では
検出に失敗することがあります。そのため検出に失敗した場合のみ、「画像の縮小」
「コントラスト強調」「閾値の緩和」を順に試します。

- 再試行で検出した写真は `detect_stage` 列が 1 以上になります。通常より検出精度が
  落ちている可能性があるため、クロップ結果の確認をおすすめします(実行後のサマリーにも
  該当ファイル名が一覧表示されます)。
- 閾値を緩めると顔の一部や背景を人物と誤認することがあるため、再試行で得た結果には
  妥当性チェック(肩と頭部が見えている・一定数以上のランドマークがある・人物が極端に
  小さくない)を課し、満たさない場合は採用せず `NO_PERSON_DETECTED` とします。
- `--no-detect-fallback` で無効にできます。

## EXIF Orientationへの対応

スマートフォンや一部のカメラで撮影した写真は、ピクセルデータ自体は横向きのまま保存され、
EXIFのOrientationタグで「表示時にどう回転するか」を指定していることがあります。

Lightroomの `crs:CropTop/Left/Right/Bottom` は**保存時(回転補正前)の座標系**を基準に
解釈されるため、本スクリプトは以下の手順で変換しています。

1. 表示向き(見たまま)に回転補正した画像で人物検出・クロップ計算を行う
2. 結果を、Orientationタグに応じて保存時の座標系に変換してからCSVに出力する

通常は意識する必要はありません。

## デバッグツール

`debug_single.py` は、1枚の写真に対する検出結果(全ランドマークの座標・visibility・
presence)、バウンディングボックス、full_body判定、クロップ範囲をコンソールに出力し、
検出結果を重ねた確認用画像を保存します。

```bash
python debug_single.py --input path/to/photo.jpg --output debug_out.jpg
```

`--mode general`(既定)/ `--mode promo` に対応しています。

## 制限

- 回転を伴うクロップ(`CropAngle` が0でない)には対応していません。学習データからも
  除外されます。
- 人物が写っていない写真は `NO_PERSON_DETECTED` となり、クロップされません。
