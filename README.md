# 人物写真クロップCSV生成 + Lightroom Classicプラグイン

元のJPGファイルには一切変更を加えず、Lightroom Classicのカタログ上でのみ
非破壊クロップを一括適用するためのツールセットです。

2つのクロップモードがあります。

- `--mode promo` (既定): 宣材写真用。人物を水平中央に配置する従来ロジック(変更なし)
- `--mode general`: 汎用ポートレート用。視線・体の向きや背景の情報量を考慮し、
  人物を必ずしも中央に置かない構図を自動選択する(詳細は末尾の章を参照)

## 構成

```
crop_calculator.py         ... 画像を解析してクロップ情報CSVを生成するPythonスクリプト(promo/general共通)
general_crop.py            ... generalモードの特徴量抽出・クロップ計算ロジック
train_general_crop_model.py ... 手動トリミング実績からgeneralモード用モデルを学習するスクリプト
requirements.txt           ... 依存パッケージ
Info.lua                    ... Lightroomプラグイン定義
ApplyCropFromCSV.lua        ... CSVを読み込みクロップを適用する本体
ExportCropHistory.lua       ... カタログのクロップ履歴をCSVに書き出す(generalモデルの学習データ作成用)
```

(上記のLua 3ファイルが1つのLightroomプラグインを構成します。インストール方法は
「3. Lightroomプラグインのインストール」を参照してください。)

## 1. Pythonスクリプトのセットアップ

```bash
pip install -r requirements.txt
```

初回実行時、姿勢推定モデル(pose_landmarker_full.task, 約30MB)を
Googleのサーバーから自動ダウンロードします。インターネット接続が必要です。

## 2. クロップ情報CSVの生成

```bash
python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv
```

サブフォルダも含めて処理したい場合は `--recursive` を追加してください。

汎用ポートレートモードを使う場合は `--mode general` を追加します(学習済みモデルが
無くてもヒューリスティックで動作します。学習済みモデルがある場合は `--model` で指定):

```bash
python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv \
    --mode general --model general_crop_model.pkl
```

### 出力CSVの列

| 列名 | 内容 |
|---|---|
| filename | ファイル名(拡張子含む) |
| path | 元画像の絶対パス。Lightroom側はこの**フルパス**で写真を特定します |
| CropTop / CropLeft / CropRight / CropBottom | 画像全体を0.0〜1.0とした場合のクロップ枠の各辺の位置 |
| full_body | 1=全身写真と判定, 0=それ以外 |
| status | OK / NO_PERSON_DETECTED(人物検出失敗。この行はLightroom側でスキップされます) |
| detect_stage | 検出に使った段階。0=通常条件。1以上は再試行で検出したもの(下記参照) |

`status` が `NO_PERSON_DETECTED` の行はクロップが計算されていません。該当写真は
CSVを見て手動で確認・修正するか、そのまま未クロップにしておいてください。

### 人物検出のフォールバック

ハイキー(白飛び気味)で低コントラストな写真では、人物がはっきり写っていても
通常の条件では検出に失敗することがあります。そのため検出に失敗した場合のみ、
「画像の縮小」「コントラスト強調」「閾値の緩和」を順に試します。

- 1段階目は従来と同一の条件なので、**これまで検出できていた写真の結果は一切変わりません**
- 再試行で検出した写真は `detect_stage` 列が 1 以上になります。通常より検出精度が
  落ちている可能性があるため、**クロップ結果の確認をおすすめします**(実行後のサマリーにも
  該当ファイル名が一覧表示されます)
- 閾値を緩めると、顔の一部や背景の模様を人物と誤認することがあります。これを防ぐため、
  再試行で得た結果には妥当性チェック(肩と頭部が見えている・一定数以上のランドマークがある・
  人物が極端に小さくない)を課し、満たさない場合は採用せず `NO_PERSON_DETECTED` とします。
  誤った検出で壊滅的なクロップになるより、未クロップのまま残す方が安全なためです
- `--no-detect-fallback` を付けると、この再試行を無効にして従来どおりの動作にできます

### クロップロジック

- 出力アスペクト比は常に元画像と同じ(ズームイン/ズームアウトのみでクロップ)
- 人物を水平方向中央に配置
- 全身写真でない場合: 頭上の余分な余白を削除しつつ、上部余白を約8%確保。左右も約8%確保
- 全身写真の場合: 人物が絶対に切れないことを優先しつつ、上下・左右ともに約8%の余白を確保
  (人物のプロポーションと画像アスペクト比の関係で、片方の余白が8%より大きくなることがあります)

パラメータ(余白率・判定の閾値など)は `crop_calculator.py` 冒頭の定数で調整できます。
特に自動検出の精度に納得できない場合は `VISIBILITY_THRESHOLD` や `HEAD_PAD_FACTOR` を
何枚かのサンプルで試しながら調整することをおすすめします。

### EXIF Orientationへの対応

スマートフォンや一部のカメラで撮影した写真は、ピクセルデータ自体は横向きのまま保存され、
EXIFのOrientationタグで「表示時にどう回転するか」を指定していることがあります。

Lightoomの`crs:CropTop/Left/Right/Bottom`はこの**保存時(回転補正前)の座標系**を基準に
解釈されるため、本スクリプトは以下の手順で正しく変換しています。

1. EXIF Orientationを読み取り、表示向き(見たまま)に回転補正した画像で人物検出・
   クロップ計算(水平中央配置など)を行う
2. 計算結果を、Orientationタグに応じて保存時の座標系に変換してからCSVに出力する

そのため、通常は特に意識する必要はありません。ただし念のため、`debug_single.py`は
表示向き座標・raw座標の両方をコンソールに出力するので、疑わしい写真があれば
確認してみてください。

## 3. Lightroomプラグインのインストール

1. このリポジトリのフォルダ(Info.lua, ApplyCropFromCSV.lua, ExportCropHistory.lua を含む)を
   そのまま任意の場所にコピーし、フォルダ名の末尾を `.lrplugin` にリネームしてください
   (例: `CropFromCSV.lrplugin`)。Pythonスクリプトと同じフォルダに置いたままで構いません。
2. Lightroom Classic を開き、`ファイル > プラグインマネージャー` から「追加」を選び、上記フォルダを指定します。
3. 対象のJPGを、通常どおりLightroomのカタログに読み込んでおきます(まだの場合)。

インストールすると `ファイル > 追加ツール` に以下の2つのメニュー項目が追加されます。

- **CSVからクロップを適用...** (`ApplyCropFromCSV.lua`): crop_calculator.py の出力CSVを適用する
- **クロップ履歴をCSVに書き出す...** (`ExportCropHistory.lua`): 既に手動でトリミング済みの写真から
  クロップ実績をCSVに書き出す(generalモデルの学習データ作成用。詳細は末尾の章を参照)

## 4. クロップの適用

1. `ファイル > 追加ツール` メニューに追加された「CSVからクロップを適用...」を選択します。
2. 手順2で生成した `crop_data.csv` を選択します。
3. マッチ件数・未検出件数の確認ダイアログが出るので、内容を確認して「適用する」を押します。
4. 完了後、適用件数・エラー件数のサマリーが表示されます。

### 注意点

- 写真の特定には**フルパス**(CSVの`path`列)を使用します。Canonなどの連番ファイル名は
  撮影日フォルダをまたいで重複することが多く(例: `052A7463.JPG` が複数フォルダに存在)、
  ファイル名だけで照合すると**別フォルダの同名写真にクロップが適用されてしまう**ためです。
  - 古い形式(`path`列が無い)のCSVを読み込んだ場合はファイル名照合にフォールバックしますが、
    カタログ内に同名ファイルが複数ある写真は誤適用を避けるためスキップされ、その件数が
    ダイアログに表示されます。その場合は `crop_calculator.py` を再実行してCSVを作り直してください。
  - 適用前の確認ダイアログに「フルパスで特定: N件 / ファイル名で特定: N件」が表示されるので、
    意図した方法で照合されているか確認できます。
- 元のJPG本体は変更されません。ただし、Lightroom側の「カタログ設定 > メタデータ」で
  「変更を自動的にXMPに書き込む」がオンになっている場合、JPGファイル内のXMPメタデータ
  (ファイル自体)に編集情報が書き込まれます。ピクセルデータ自体は変更されませんが、
  「元のJPGに一切触れたくない」場合はこの設定をオフのままにしてください。
- 1000枚規模の一括適用になるため、**必ず事前にカタログのバックアップを取り**、
  まず数枚〜数十枚のテストデータで動作確認してから全件に適用することを強く推奨します。
- Lightroom Classic の SDK バージョンにより `photo:applyDevelopSettings` の挙動が
  異なる場合があります。手元のLightroomバージョンで少数サンプルでのテストをお願いします。

## 5. 汎用ポートレートクロップ(`--mode general`)

宣材写真用ロジック(`--mode promo`、既定)は一切変更していません。`--mode general` は
それとは別の構図方針を持つ、独立した追加オプションです。

### promoモードとの違い

| | promo(既定) | general |
|---|---|---|
| 水平配置 | **鼻**の位置を画像の中央に合わせる | **体全体(バウンディングボックス)の中心**を画像の中央に合わせる |
| 余白の決め方 | 固定の余白率(定数) | 背景の情報量(エッジ密度)に応じて余白を調整。学習済みモデルがあればそちらを優先 |
| 用途 | 宣材写真など、規格を揃えたい場合 | スナップ写真など、写真ごとに最適な構図を選びたい場合 |

出力CSVのフォーマットは promo と全く同じなので、`ApplyCropFromCSV.lua` はそのまま
generalモードのCSVにも使えます。

#### 水平方向の中央配置について

どちらのモードも人物を水平中央に配置しますが、**基準が異なります**。promoモードは鼻を
基準にするため、顔の向きによっては体全体が中央からずれて見えることがあります
(実測で最大±18%程度)。generalモードは体全体の中心を基準にするため、この差が出ません。

- 予測された左右の余白(L, R)は、クロップの**幅**の決定にのみ使われます
- 人物が画像の端に寄っていて、中央配置すると人物が切れてしまう場合は、
  **人物が切れないことを優先**して中央配置を断念します
- `general_crop.py` の `HORIZONTAL_CENTER_WEIGHT` を 1.0 から下げると、視線・体の向きに
  応じた左右非対称の配置(いわゆる「空間」を残す構図)を混ぜられます(0.0で完全に非対称配置)

### モデルなしで使う(ヒューリスティック)

学習済みモデルを用意しなくても、`--mode general` だけで動作します。人物のポーズ検出
(promoと同じ処理)に加えて、Pillowベースの簡易エッジ密度解析で「背景のうるささ」を
推定し、経験則(三分割法+視線方向+背景密度)でクロップを決めます。まずはこの状態で
試してみて、狙いと合わない場合は次項の学習データで調整してください。

### 手動トリミング実績をモデルの学習データにする

はい、可能です。以下の流れで、実際にトリミングした1000枚超の実績を評価・学習データに
変換できます。

1. **Lightroomプラグインでクロップ履歴を書き出す**
   `ファイル > 追加ツール > クロップ履歴をCSVに書き出す...`(`ExportCropHistory.lua`)を実行します。
   対象は選択中の写真(未選択ならフォルダ/コレクション内の全写真)なので、事前に
   手動トリミング済みの写真が入ったフォルダ/コレクションを選んでおくと絞り込めます。
   出力されるCSVには、ファイル名・元ファイルパス・実際のクロップ値
   (`crs:CropTop/Left/Right/Bottom`, `CropAngle`)・クロップ済みかどうかのフラグが入ります。
   元のJPGやカタログへの書き込みは一切行いません(読み取り専用)。

2. **モデルを学習する**

   ```bash
   pip install scikit-learn
   python train_general_crop_model.py --crop-csv crop_history.csv \
       --images-dir /path/to/jpg_folder --output-model general_crop_model.pkl
   ```

   `--images-dir` は、CSVの `path` 列が(別のPCで書き出した等の理由で)使えない場合の
   フォールバック検索先です。ファイル名の重複がなければ、`path` 列だけで解決できることが
   ほとんどです。

   学習の中身: 各写真についてpromoモードと同じ人物検出を行い、実際のクロップ矩形を
   「人物のバウンディングボックスに対する上下左右の余白比率」に変換したうえで、
   4つの軽量な回帰モデル(勾配ブースティング木)を学習します。回転クロップ
   (`CropAngle` が0でない)や、クロップされていない写真は自動的に除外されます。
   実行後、ホールドアウトデータでのMAE(誤差)と、実際のクロップ枠とのIoU(重なり度、
   1.0に近いほど良い)が表示されるので、精度の目安として確認してください。

3. **学習したモデルを使う**

   ```bash
   python crop_calculator.py --input /path/to/jpg_folder --output crop_data.csv \
       --mode general --model general_crop_model.pkl
   ```

   写真を追加でトリミングしたら、手順1〜2を再実行すればモデルを更新できます。

### 制限・チューニングのヒント

- 背景の「情報量」は、本格的な顕著性(サリエンシー)モデルではなく、Pillowの
  エッジ検出による簡易近似です(追加の重い依存を避けるため)。特定の被写体
  (強いボケ、逆光、単色背景など)でうまく機能しない場合は `general_crop.py` 冒頭の
  `BAND_RATIO` / `DENSITY_ADJUST_STRENGTH` 等の定数を調整してください。
- 1000枚規模であれば勾配ブースティング木による回帰で十分実用的な精度が見込めますが、
  データが少ない/偏っている場合は特定の構図(全身、逆光、複数人物など)に対する予測が
  不安定になることがあります。`full_body` (全身/半身)ごとに手動トリミング枚数の
  バランスが取れていると学習が安定しやすいです。
- 複数人物が写っている写真は、現状のポーズ検出が最も信頼度の高い1人のみを対象にする
  ため、意図と異なる人物を基準にクロップされる可能性があります。
- 予測結果はモデルの学習データの傾向に強く依存します。当然ながら、学習データに
  含まれない極端な構図(かなり寄った写真、複雑なポーズなど)では精度が落ちる点に
  ご留意ください。
